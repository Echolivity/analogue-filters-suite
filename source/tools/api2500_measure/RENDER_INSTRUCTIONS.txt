API 2500 MEASUREMENT PACK
=========================

What this is for
----------------
These test signals, run through an API 2500 (hardware, or the Waves / UAD plugin), let us measure what API never
published: the knee widths, the detector speed, how VARIABLE release behaves, the THRUST MED curve and the link
SHAPE filters.

How to render
-------------
1. Session at 48 kHz. Put the compressor on a STEREO track, nothing else on the track or master.
2. Before EVERY render, set the compressor to these BASE SETTINGS, then change only what the table below says:
     THRESHOLD   -20 dBu (its lowest setting)   ->  Waves: -42 dBFS
     RATIO       4:1          KNEE      HARD
     ATTACK      1 ms         RELEASE   50 ms (fixed, not VAR)
     THRUST      NORM         TYPE      NEW (feed-forward)
     L/R LINK    100 %        SHAPE     (as table, otherwise leave default)
     MAKEUP      AUTO OFF, makeup/output 0 dB      MIX 100 %      TILT / TRIM 0
     Waves only: Analog OFF (if your version has it).
3. Bounce/export each render as 24-bit (or 32-bit float) WAV, full length, no normalising, no dither.
   Keep the file's start: the click at 0.5 s is used to line things up, so do not trim it.
4. Name each render exactly as in the "Save as" column and send them all back (zip is fine), plus one line saying
   what you used (hardware model / Waves / UAD, and version).

Hardware only: also record 00_calibration with the unit BYPASSED and tell me your interface's level
(e.g. "0 dBFS = +18 dBu"), so I can convert dBFS to dBu.

What each one measures
----------------------
 R02-R05  input stepped -60..-1 dBFS in 1 dB steps -> the static curve: threshold, ratio and each knee's width;
          OLD (feedback) curve.
 R06-R08  third-octave tones 20 Hz-20 kHz at a fixed level -> how much each frequency drives the detector:
          the THRUST MED and LOUD curves (NORM is the reference).
 R09-R11  level jumps of 40 dB -> attack shape and the RMS detector's own speed (at 30 us the detector dominates).
 R12-R13  bursts 2, 17 and 32 dB over threshold -> whether VARIABLE release slows down after heavier compression.
 R19-R20  a sine and a spiky pulse train at the same RMS level -> whether the detector reacts to RMS (both compressed
          alike) or to peaks (the pulse train compressed more).
 R14-R17  loud tones on Left only, quiet steady tone on Right -> how the link passes Left's gain reduction to Right
          at each frequency: the SHAPE filters.

The files' exact timings are in schedule.json (used by the analysis; you don't need it).
